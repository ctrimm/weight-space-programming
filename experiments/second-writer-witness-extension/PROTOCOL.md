# Protocol — second-writer replication of the witness extension (pre-registered)

Written 2026-11-02 before any API call for this experiment. Cory
authorized this run explicitly after being given a cost estimate of
roughly $0.35, grounded in the measured per-call costs from the
first second-writer pilot.

## Question

GPT-5.6 Sol and Gemini 3.1 Pro previously replicated exact weight
compilation for SNAP, SSI (individual), and Medicaid patient
liability. Can they also compile the two harder witness-extension
rules written later by Muse Spark?

1. **Medicaid medically-needy share of cost (California)**, which
   reuses SSI income counting as a subroutine and subtracts medical
   expenses after the count.
2. **SSI couple payment**, which combines two people's incomes before
   counting and applies the exclusions once per couple.

## Design

- **Writers:** `openai/gpt-5.6-sol` and
  `google/gemini-3.1-pro-preview`, called through OpenRouter. Both
  remain outside the Anthropic family.
- **Tasks:** the stipulated rules and fixed architectures are
  restated in full in each prompt. No evaluation points, oracle code,
  original weights, construction scripts, or derivations are shared.
- **Prompts:** the exact prompt for each model/task is generated by
  `run_replication.py` from the constants in that file. Before the
  first model call, the runner writes SHA-256 hashes of all four
  prompts to `results/prompt_freeze.json`.
- **Output format:** the same sparse JSON serialization as the first
  second-writer pilot. Unlisted entries are zero; every named array
  must be present with its fixed shape.
- **Attempts:** one call per model x task. If a reply cannot be
  parsed as the specified JSON, exactly one syntax-repair retry is
  allowed. The retry receives only the parse error; it never receives
  scores, evaluation points, oracle information, or hints. Refusals
  and unparsable second replies are recorded as no submission.
- **Scoring:** only after all calls finish. Scores use the two
  original witness-extension evaluation designs unchanged, including
  the share-of-cost audit probes and the couple zero-member slices.
  Gates are unchanged: PASS = maximum absolute error <= $0.01;
  Partial <= $1; otherwise FAIL. No-submission cells are FAIL for
  gate purposes, with the reason reported separately.
- **Weights freeze:** after all calls and before scoring, SHA-256
  hashes of every submitted `.npz` are recorded in
  `weights/FREEZE.json`.

## Cost discipline

- Planning estimate: approximately **$0.35**, based on the first
  pilot's measured response costs (GPT-5.6 Sol: $0.014-$0.053 per
  submitted construction; Gemini 3.1 Pro: $0.056-$0.201).
- Hard cap: **$0.75 cumulative measured spend for this experiment**.
  The runner checks cumulative response-reported cost before every
  call and aborts before starting another call once the cap has been
  reached. The allowance above the estimate covers output-length
  variance and the protocol's single syntax-repair retry; it is not
  permission for extra tasks, extra models, or score-feedback calls.
- Every call's cost is taken from OpenRouter's response usage
  accounting. The runner also records account-level total usage
  before and after the run from the free credits endpoint; any lag
  or discrepancy between response-level and account-level accounting
  will be reported rather than silently reconciled.

## Declared asymmetries

As in the first pilot, the API writers get one stateless prompt while
the original writer worked interactively in-session. The sparse JSON
format also favors sparse constructions. These biases are part of
the test conditions and will be repeated in the results.
